# 轻益点 APP 改造时间线与阶段交接

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement detailed implementation plans derived from this roadmap. This file is the project timeline and user handoff record, not the final task-by-task implementation plan.

**Goal:** 将当前 uni-app/Vue 项目分阶段改造成“轻益点体重与代谢健康管理 APP/小程序”。

**Architecture:** 先复用现有前端页面和接口完成业务壳与用户路径改造，再逐步补齐健康档案、打卡、趋势报告、AI 推荐和后端数据接口。每个阶段结束时必须明确告诉用户需要做什么、需要确认什么、是否需要提供后端/API/素材支持。

**Tech Stack:** Vue 2, uni-app, uView, uni-ui, existing API layer in `common/api/index.js`.

## Global Constraints

- 固定遵循根目录 `AGENTS.md` 中的“轻益点 APP 改造 Harness v1”。
- 用户端产品名优先使用“轻益点”，公司/品牌背书使用“瘦益斐浅”。
- 业务依据优先来自 `v2-受益斐浅计划书.pdf`。
- 默认不引入新 UI 框架，默认复用现有页面结构和样式体系。
- 所有健康建议必须使用谨慎表达，不写“治愈”“保证减重”“替代药物”“无风险”。
- 涉及疾病、用药、严重不适时必须提示咨询医生。
- AI 不能替代医生诊断。
- 健康数据必须强调用户授权、隐私保护和数据安全。

- `pages/message/conversation-list.vue`
- `pages/psychologist/index.vue`

**主要交付：**

- AI 对话模块改名为“轻益点智能顾问”，文案聚焦健康管理、产品使用和打卡建议。

### 阶段 3：健康档案与打卡趋势

**目标：** 从“可演示”升级到“能沉淀用户健康数据”。

**主要新增能力：**

- 健康档案：身高、体重、BMI、腰围、体脂、目标体重、基础病史、产品使用状态。
- 今日打卡：体重、服用情况、饮食、运动、睡眠、情绪、身体反馈。
- 趋势报告：体重曲线、腰围变化、睡眠/情绪变化、服用依从性。

**建议新增或调整页面：**

- `pages/health-profile/index.vue`
- `pages/checkin/index.vue`
- `pages/report/index.vue`
- `pages/user/index.vue`
- `pages.json`

**建议后端接口：**

- `GET /health/profile`
- `PUT /health/profile`
- `POST /health/checkins`
- `GET /health/checkins`
- `GET /health/reports/summary`

**验收标准：**

- 用户能建立健康档案。
- 用户能完成一次今日打卡。
- 用户能看到基础趋势或阶段总结。
- 相关页面明确提示数据授权和隐私保护。

**阶段结束时需要用户操作：**

- 确认健康档案字段是否够用，尤其是是否需要加入血糖、血脂、血压、肝功能、菌群检测等字段。
- 确认后端是否已经提供健康档案和打卡接口。
- 如果后端还没做，确认是否继续使用本地模拟数据演示。

### 阶段 5：AI 推荐与运营闭环

**目标：** 对齐计划书中的“AI 赋能用户反馈与数据分析系统”，形成数据驱动服务。

**主要能力：**

- AI 基于健康档案、测评结果、打卡数据给出个性化建议。
- 根据用户状态推荐基础服务、增值服务或尊享服务。
- 推送饮食、运动、睡眠、情绪、服用提醒。
- 收集产品体验、依从性、不良反应和满意度反馈。

**建议后端能力：**

- AI 系统提示词按轻益点健康顾问重写。
- AI 请求上下文可读取用户健康档案和最近打卡摘要。
- 敏感健康问题触发合规提醒。

**验收标准：**

- AI 回答不再像职业顾问。
- AI 能引用用户健康档案和近期记录给出建议。
- 涉及疾病、用药、严重不适时能提示就医。
- AI 建议使用“辅助、参考、建议、有助于”等谨慎表达。

**阶段结束时需要用户操作：**

- 试问 AI 5 类问题：产品用法、减重建议、睡眠情绪、身体不适、是否替代药物。
- 确认 AI 语气是否符合品牌：专业、温和、谨慎、有陪伴感。
- 告诉我是否要接入真实大模型配置或继续使用当前后端 AI。

### 阶段 6：运营功能与商业化增强

**目标：** 支撑计划书中的 B2C、社区活动、会员体系、复购和服务分层运营。

**主要能力：**

- 积分、勋章、挑战赛。
- 优惠券、疗程券、试用装领取。
- 会员等级和权益。
- 社区健康服务点。
- 产品套餐和外部电商跳转。
- 活动报名、社群入口。

**验收标准：**

- 用户完成打卡/测评/预约后能获得权益或下一步转化入口。
- 社区、医院、企业渠道有可展示入口。
- 会员权益与基础/增值/尊享服务层级一致。

**阶段结束时需要用户操作：**

- 确认是否需要真实支付/商城，还是只做外部电商跳转。
- 提供优惠券、积分、会员等级规则。
- 提供社区服务点、合作机构、客服联系方式等真实数据。

### 阶段 7：高级数据能力与 B2B 扩展

**目标：** 面向长期产品化，扩展菌群检测、可穿戴设备、机构随访和真实世界数据沉淀。

**主要能力：**

- 居家粪便采样/菌群检测记录。
- 体脂秤、手环、睡眠设备数据接入。
- 医院/社区/企业机构端随访。
- 用户分群、产品响应预测、研发反馈。

**验收标准：**

- 用户授权后可记录更高阶数据。
- 机构端能查看授权用户随访数据。
- 数据结构能支持后续 AI 分析和产品迭代。

**阶段结束时需要用户操作：**

- 确认是否真的要做 B2B/机构端。
- 提供检测机构、设备平台或第三方接口资料。
- 确认隐私授权文本和数据使用边界。

每个阶段完成后，回复必须包含：

- **本阶段完成了什么**

- **发现的风险或遗留问题**
- **下一阶段建议**

“需要用户操作什么”必须明确到动作，例如：

- 请运行并试走某条路径。
- 请确认某组文案。
- 请提供 logo/产品图/API 文档。
- 请让后端返回某个字段。
- 请决定是否进入下一阶段。
